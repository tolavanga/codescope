# CodeScope — локальный анализ кода

Инструмент для разработчиков: статистика исходников, карта строк, сравнение версий, сниппеты и JSON-отчёты. Весь анализ выполняется локально в браузере.

## Возможности

- вставка кода или локальное чтение до 12 текстовых файлов, до 300 КБ каждый;
- JavaScript, TypeScript, Python, CSS, HTML, JSON и TXT;
- строки кода, комментарии, функции, ветвления, TODO и вложенность;
- языковой состав, карта строк, плотность ветвлений и таблица файлов;
- построчное сравнение двух версий с изменением метрик;
- поиск и копирование четырёх сниппетов;
- локальный экспорт JSON-отчёта;
- тёмная и светлая темы, адаптивный интерфейс и PWA-установка.

Метрики эвристические: они не заменяют AST-анализ, линтер, тесты или профилировщик. Код не исполняется, не отправляется в сеть и не сохраняется. Внешние API не используются.

## Локальный запуск

Требуется Node.js 22 или совместимая актуальная LTS-версия.

```bash
npm ci
npm run dev
```

Проверка production-сборки:

```bash
npm run build
npm run preview
```

Готовые статические файлы появятся в `dist/`.

## Публикация на GitHub Pages

Workflow `.github/workflows/deploy.yml` уже настроен.

1. Создайте на GitHub репозиторий с именем `codescope`.
2. Загрузите в него все файлы проекта, включая скрытую папку `.github`. Основная ветка должна называться `main`.
3. В репозитории откройте **Settings → Pages**.
4. В разделе **Build and deployment → Source** выберите **GitHub Actions**.
5. Откройте вкладку **Actions**, разрешите выполнение workflows, если GitHub попросит это сделать, и дождитесь зелёного статуса **Deploy to GitHub Pages**.
6. Сайт будет доступен по адресу `https://<USERNAME>.github.io/codescope/`.

Каждый следующий push в `main` автоматически соберёт и опубликует новую версию. Ручной запуск доступен через **Actions → Deploy to GitHub Pages → Run workflow**.

### Собственный домен

После покупки домена укажите его в **Settings → Pages → Custom domain**, затем добавьте DNS-записи по инструкции GitHub у своего регистратора. Не добавляйте домен в настройки, пока он не зарегистрирован на вас.

## Приватность и безопасность

CSP задана в `index.html`; GitHub Pages не поддерживает произвольные HTTP-заголовки через `_headers`. Статический сайт и клиентские ограничения не могут гарантировать полную защиту от взлома или копирования идеи.
